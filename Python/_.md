

# Ground rules (fixed)

- **Language/runtime:** Python 3.12, async-first.
    
- **Frameworks/libs:** FastAPI + Uvicorn • SQLAlchemy 2.0 (async) + Alembic • psycopg[binary] • Pydantic v2 • Redis 7 (aioredis) • Celery 5 (Redis broker) • boto3 (S3/MinIO) • httpx (client) • structlog • prometheus-fastapi-instrumentator • OpenTelemetry (fastapi, psycopg, logging).
    
- **DB:** PostgreSQL 15.
    
- **Repo layout:**  
    `apps/api` (FastAPI), `apps/worker` (Celery), `infra/` (docker-compose + Nginx + MinIO), `libs/` (shared code), `docs/`.
    
- **Tooling:** pytest + pytest-asyncio + coverage • ruff + black + mypy (strict) • pre-commit • k6 for load.
    
- **Capstone (unchanged):** “Workboard” (boards/lists/cards/comments/uploads/activity feed). Minimal HTML pages or API-only if you prefer—focus is backend SDE skills.
    
- **Cadence (5d/wk):** Build 90 min → DSA 30–45 min (one problem, tests, complexity) → Notes/DoD 20 min.
    
- **Allowed refs:** Official docs for the above only. No tutorials/videos.
    
- **Every DoD includes:** tests green (unit+integration), type check clean (mypy), lint clean (ruff), `docker compose up` works from a clean clone, short design note in `docs/`.
    

# Proficiency targets

- APIs & data: validation, **cursor pagination**, indexing, transactions, migrations, idempotency.
    
- Reliability: retries+jitter, **DLQ**, circuit breaker, rate limiting, backpressure.
    
- Security: auth (access/refresh), RBAC, input limits/validation, safe uploads, secrets.
    
- Observability: structured logs, RED metrics, basic traces.
    
- Performance: profiling, SQL plans, caches, avoiding N+1.
    
- System design: requirements, constraints, scale math, trade-offs.
    
- **DSA (minimal):** arrays/strings/maps/sets; **binary search**; **two-pointers** (merge/intersect/windowing); **sliding window**; **stack/queue**; BFS on trees; heap awareness.

## Phase 0 (½ day) — Environment & scaffolding

**Deliverable:** Monorepo bootstrapped; CI for lint/test.  
**DoD:** `make up` starts Postgres/Redis/MinIO/Nginx; `make test` green; mypy/ruff clean.

---

## Phase 1 (Week 1) — HTTP & foundation

**Deliverable:** FastAPI service skeleton (versioned routes, error envelope).  
**Scope:** Pydantic models; exception handler; request IDs; Nginx reverse proxy; httpx client with timeouts/retries.  
**DSA:** arrays/strings/maps/sets (daily).  
**DoD:** `/v1/health` with JSON `{status, request_id}`; p95 < 50 ms at 100 rps (k6).

---

## Phase 2 (Week 2) — Data modeling & SQL

**Deliverable:** Schema + Alembic migrations: `users, boards, memberships, lists, cards, comments`.  
**Scope:** FKs, constraints; indexes: `(boards.owner_id)`, `(lists.board_id, position)`, `(cards.list_id, position, id)`, `(comments.card_id, created_at)`. Transactional multi-row ops.  
**DSA:** two-pointers (merge/intersect), sort-key reasoning `(ts,id)`.  
**DoD:** `EXPLAIN ANALYZE` shows index usage on list/card queries; safe up/down migrations.

---

## Phase 3 (Week 3) — CRUD + validation + **cursor pagination**

**Deliverable:** Boards/Lists/Cards CRUD; **seek pagination** (`cursor=base64(ts,id)`; `limit`).  
**Scope:** Pydantic validation; optimistic concurrency via `updated_at` precondition; error codes.  
**DSA:** two-pointers merge (server page + optimistic items), binary search for insert position.  
**DoD:** concurrency test inserts during paging → no dupes/misses across 3 pages.

---

## Phase 4 (Week 4) — Auth & RBAC

**Deliverable:** Email/password auth; **refresh rotation**; RBAC (owner/admin/member).  
**Scope:** passlib[bcrypt]; PyJWT; refresh token store (Postgres) with rotation+revocation; dependency-based guards; CORS.  
**DSA:** **sliding window** login limiter (Redis) + guard chain (stack).  
**DoD:** token theft simulation invalidates old refresh; limiter enforces thresholds with unit tests.

---

## Phase 5 (Week 5) — Caching & rate limiting

**Deliverable:** Read-through Redis cache for hot GET; **token bucket** limiter on writes.  
**Scope:** cache keys/TTL/refresh-ahead; stampede control (single-flight); 429 policy; invalidation on write.  
**DSA:** sliding window vs token bucket (O(1) ops), brief Lua script or atomic pipelines.  
**DoD:** >80% hit rate on hot key under synthetic load; limiter stable under burst test.

---

## Phase 6 (Week 6) — Async jobs & reliability

**Deliverable:** Celery worker for activity events + email digest mock.  
**Scope:** retries with **exponential backoff + jitter**; **DLQ** for poison tasks; **idempotency keys**; outbox table for event emission.  
**DSA:** queue discipline; heap awareness (delayed jobs scheduling).  
**DoD:** replayed events don’t duplicate effects; DLQ captures failures with metadata.

---

## Phase 7 (Week 7) — Files & streaming

**Deliverable:** Attachment uploads via **pre-signed URLs** (MinIO/S3).  
**Scope:** streaming uploads/downloads; content-type/size checks; antivirus stub; thumbnail worker.  
**DSA:** bounded buffers/backpressure via asyncio streams.  
**DoD:** large file doesn’t buffer in RAM; thumbnails generated; e2e upload spec green.

---

## Phase 8 (Week 8) — Filtering & safe query compilation

**Deliverable:** Advanced `GET /comments` filters: `author`, `date range`, `has:attachment`, `(tag:red OR tag:blue) AND not:archived`.  
**Scope:** **Shunting-yard** (stack) to RPN → AST; compile to **parameterized SQL**; field allow-list; hard limits/timeouts.  
**DSA:** stack for parse; queue/BFS for AST validation.  
**DoD:** injection attempts fail safely; `EXPLAIN` shows bounded plans; property tests (hypothesis) cover parser.

---

## Phase 9 (Week 9) — Observability & SLOs

**Deliverable:** RED metrics + basic traces.  
**Scope:** prometheus-fastapi-instrumentator; structured logs (structlog); OpenTelemetry across API→DB→worker; SLI/SLO + error budget doc.  
**DoD:** dashboard screenshot in `docs/`; alert fires when p95 latency > SLO for 10 min.

---

## Phase 10 (Week 10) — Performance pass

**Deliverable:** Hot-path optimization with before/after evidence.  
**Scope:** cProfile/py-spy; SQL plan tuning; batch queries; remove N+1; cache warming; verify seek pagination under load.  
**DSA:** binary search bounds; two-pointers for k-way merges (if needed).  
**DoD:** ≥2× throughput on target endpoint without correctness regressions.

---

## Phase 11 (Week 11) — Security & hardening

**Deliverable:** Baseline security posture.  
**Scope:** CSP, strict CORS, CSRF for cookie flows (if used), secrets rotation plan, audit log for auth/role changes, input size/time limits, PII handling.  
**DoD:** OWASP “A-grade” checklist items documented; zap/burp basic scan clean.

---

## Phase 12 (Week 12) — Delivery & deployment

**Deliverable:** Containerized deploy (Fly.io/Render/Railway/EC2).  
**Scope:** health checks; migration on startup; blue/green or rolling; seed script; rollback; cost estimate for target QPS.  
**DoD:** one-command local run; public URL; smoke tests green post-deploy.

---

## Phase 13 (Week 13) — Testing depth

**Deliverable:** Mature test suite.  
**Scope:** pytest unit + async integration (testcontainers or Compose); contract tests (OpenAPI schema validation); property-based tests (hypothesis) for parser; k6 load tests with thresholds.  
**DoD:** >80% statements; no flaky tests; load meets SLO.

---

## Phase 14 (Week 14) — System design drills & interview prep

**Deliverable:** Three 2-page design docs + rehearsed walkthroughs.  
**Drills:** URL shortener @10k rps; rate-limited API gateway; realtime comments via WebSocket fan-out. Include requirements, scale numbers, storage, caching, failures, SLOs, cost.  
**DSA (daily, 45 min):** final 10-problem set (arrays/strings, two-pointers, sliding window, stack/queue, simple BFS; 1–2 heap problems).  
**DoD:** each doc ≤2 pages + diagram; 20-minute narrative practiced.

---

## Minimal DSA set (50 problems, fixed)

- **Arrays/Strings (16):** dedup, group anagrams, longest substring (sliding window), merge intervals, rotate array, run-length encode.
    
- **Hash/Set (8):** two-sum variants, frequency maps, stable dedup.
    
- **Binary Search (8):** lower/upper bound, search insert, peak element, “binary search on answer.”
    
- **Two-Pointers (10):** merge two/k sorted lists (successive merges), intersect postings lists, partition by predicate, visible-window math.
    
- **Stack/Queue (6):** valid parentheses, RPN eval, monotonic stack min-window, BFS level order.
    

**Rules:** 1 problem/day → write tests → state complexity → stop at 45 min (log unfinished work).

---

## Promotion rubric (gate to “proficient”)

- **API correctness:** CRUD + seek pagination + validation + idempotency work under concurrency.
    
- **Data discipline:** indexes evidenced by `EXPLAIN`; transactions where required; no N+1.
    
- **Reliability:** retries with jitter; DLQ populated; circuit breaker prevents cascades.
    
- **Security:** auth/refresh robust; inputs validated; secrets managed; uploads safe.
    
- **Observability:** dashboards + traces show request path; SLOs defined/enforced.
    
- **Performance:** hot endpoint meets p95 target with profiling-led fixes.
    
- **Design communication:** clear constraints, trade-offs, and cost.
    
- **DSA:** minimal set implemented and explained under time pressure.
